# FAA2026 Project Repository

## Setup

Clone this repository:

```bash
git clone https://github.com/sorrachai/FAA2026_project.git
cd FAA2026_project
```

We recommend hosting your project on GitHub (or a similar service). Version control lets you
track your changes, collaborate in a structured way and keep a backup of your work.

To host your project on GitHub, create a new, empty repository there, then run the following from
your local clone (replace the URL with your repository's):

```bash
git remote rename origin upstream
git remote add origin https://github.com/<your-username>/<your-repository>.git
git push -u origin HEAD
```

Keeping this repository as `upstream` lets you pull in later course updates with
`git pull upstream main`.

You don't have to use this repository for your project. However, our grading tests are written
for this repository. If they don't run on your project, your solution will not be graded.

## Recommendations

### Project organization

Plan how you want to organize your repository before you start. We recommend keeping definitions,
theorem statements and proofs in separate files. This makes your project easier for us to
understand, and makes it easier to tell which parts are your own work, especially if your
submission contains thousands of lines of AI-generated proofs.

Document your contribution in your project's `README.md`: state which definitions, statements and
proofs you wrote yourself and which were generated by AI. **Warning:** You will not receive any
points if we cannot distinguish AI-generated code from your own contribution.

### Time management

Start by formalizing your definitions and models. Most of your grade depends on how well you
translate an informal problem about complexity notions into Lean. AI-generated proofs should
mainly be used to prove results about examples that show your definitions were chosen
appropriately.

### Keep the project building

Run `lake build` before every push, and push small, working steps rather than one large change at
the end. Mark unfinished proofs with `sorry` instead of leaving code that doesn't compile. Before
you submit, run `#print axioms` on your main theorems and check that the output does not mention
`sorryAx`.

### Style guidelines

We do not grade or enforce any particular style, but readability can affect how your solution is
assessed. If you plan to contribute your code to a public repository afterwards, consider
following Mathlib's [style guide](https://leanprover-community.github.io/contribute/style.html) and
[naming conventions](https://leanprover-community.github.io/contribute/naming.html).
